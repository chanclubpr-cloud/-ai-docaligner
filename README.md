# AI DocAligner คืออะไร และทำงานอย่างไร

## ภาพรวม

AI DocAligner เป็นเว็บเครื่องมือช่วย**ตรวจสอบและจัดลำดับหัวข้อในเอกสาร Word (.docx)** ให้ถูกต้องตามมาตรฐานวิชาการ เช่น เล่มวิทยานิพนธ์ เล่มขอตำแหน่งวิชาการ หรือคู่มือปฏิบัติงาน

**จุดเด่นสำคัญ 3 ข้อ:**

- **ทำงานในเบราว์เซอร์ล้วนๆ** — ไม่มีการส่งไฟล์เอกสารออกไปที่เซิร์ฟเวอร์ใดๆ ทั้งสิ้น เปิดเว็บแล้วไฟล์จะถูกประมวลผลอยู่ในเครื่องของผู้ใช้เองเท่านั้น
- **ไม่ใช้ AI ในการตัดสินใจ** — ใช้กฎตายตัว (เช่น นับจำนวนจุดในเลขนำหน้า) ในการตรวจสอบ ทำให้ผลลัพธ์แม่นยำ 100% และทำนายผลได้ทุกครั้ง ไม่มีการ "เดา" หรือ "หลอน" แบบที่ AI ทั่วไปอาจทำ
- **ไม่แตะเนื้อหา** — ปรับแค่ "รูปแบบ" ของหัวข้อ (Style, ระยะเยื้อง, การจัดหน้า) เท่านั้น ไม่มีการเปลี่ยนแปลงตัวอักษร คำ หรือเลขลำดับใดๆ ในเนื้อหาเอกสารเลย

---

## Workflow การทำงาน (3 ขั้นตอน)

### ขั้นตอนที่ 1: แนบไฟล์เอกสาร

ผู้ใช้ลากไฟล์ .docx มาวาง หรือคลิกเลือกไฟล์ ระบบจะอ่านโครงสร้างไฟล์ทันที (โดยไม่ต้องอัปโหลดไปไหน) และเตรียมข้อมูล 3 อย่างจากไฟล์นั้นไว้ล่วงหน้า:

1. **สไตล์หัวข้อที่มีอยู่จริงในไฟล์** — ไฟล์ Word แต่ละไฟล์อาจตั้งชื่อ "Heading1" "Heading2" ไว้ไม่เหมือนกัน (บางไฟล์ที่แปลงมาจาก Google Docs อาจใช้แค่ตัวเลข "1" "2" "3" แทน) ระบบจะอ่านค่าที่แท้จริงจากไฟล์นั้นๆ ไว้ก่อน แทนที่จะเดาเอาเอง
2. **ระยะ Tab มาตรฐานของไฟล์** — แต่ละไฟล์อาจตั้งระยะ Tab ไม่เท่ากัน ระบบอ่านค่าจริงมาใช้คำนวณระยะเยื้องให้ตรงกับที่ Word จะแสดงผลจริง
3. **ขนาด/ความหนาของแต่ละ Heading** — เพื่อโชว์ให้ผู้ใช้เห็นว่า "ถ้าเลือกระดับนี้ หน้าตาจะเป็นแบบไหน" ก่อนตัดสินใจ

### ขั้นตอนที่ 2: ตรวจสอบและเสนอรายงานปรับแก้

กดปุ่ม "สแกน" แล้วระบบจะ:

- ไล่อ่านทุกย่อหน้าในเอกสาร แล้ว**จำแนกประเภท**ว่าแต่ละย่อหน้าคืออะไร (อธิบายรายละเอียดในหัวข้อถัดไป)
- เทียบ Style ปัจจุบันของแต่ละหัวข้อ กับ Style ที่ "ควรจะเป็น" ตามกฎ แล้วแสดงเป็นตารางให้ผู้ใช้เห็นก่อนว่าจะแก้อะไรบ้าง (ยังไม่แก้จริง แค่เสนอ)
- แสดง**คำเตือน**ถ้าพบความผิดปกติ เช่น เลขหัวข้อซ้ำกัน เลขกระโดดข้าม หรือจุดที่ระบบตัดสินใจไม่ได้ชัดเจน
- ให้ผู้ใช้เลือกได้ว่าจะให้ระบบปรับ Tab / ระยะเยื้อง / การจัดหน้าชิดซ้าย ด้วยหรือไม่ (ไม่บังคับ เพราะบางเอกสารทางการอาจต้องการควบคุมการเปลี่ยนแปลงอย่างระมัดระวัง)

ผู้ใช้ตรวจสอบตารางที่เสนอมา แล้วกด **"อนุมัติ"** ถึงจะแก้ไขไฟล์จริง (หรือกด "ยกเลิก" ถ้าไม่พอใจผลลัพธ์)

### ขั้นตอนที่ 3: จัดโครงสร้างเสร็จสมบูรณ์

ระบบสร้างไฟล์ .docx ใหม่จากไฟล์ต้นฉบับ (ไม่ทับไฟล์เดิม) ให้ดาวน์โหลด พร้อมคำแนะนำให้เปิดตรวจสอบใน Microsoft Word อีกครั้งก่อนนำไปใช้งานจริง

## ตรรกะเบื้องหลัง: ระบบจำแนกย่อหน้าอย่างไร

หัวใจของระบบคือการไล่อ่านทุกย่อหน้าในเอกสารตามลำดับ แล้วจัดแต่ละย่อหน้าเข้าพวกใดพวกหนึ่งต่อไปนี้:

| ประเภท | ตัวอย่าง | ระบบทำอะไรกับมัน |
|---|---|---|
| **บทที่** | "บทที่ 1" | ถือเป็นหัวข้อระดับบนสุดเสมอ (Heading1) |
| **หัวข้อจุด** | "1.1 ความเป็นมา", "3.3.1 กลไก..." | นับจำนวนจุดเพื่อกำหนดระดับ Heading และคำนวณระยะเยื้อง |
| **รายการวงเล็บ** | "1)", "1.1)" | ใช้จัดระยะเยื้องเท่านั้น ไม่นับเป็นหัวข้อหลักในสารบัญ |
| **เลขเปล่า** | "1.", "2." | ความหมายกำกวม ต้องดูบริบทเพิ่ม (อธิบายด้านล่าง) |
| **ย่อหน้าเนื้อหา** | ข้อความทั่วไป | เกาะระยะเยื้องกับหัวข้อที่ใกล้ที่สุดก่อนหน้า |
| **เนื้อหาในตาราง** | ตัวเลขในตารางสถิติ | ส่วนใหญ่ไม่แตะเลย (ป้องกันไปยุ่งกับข้อมูลตาราง) |

**เงื่อนไขสำคัญ:** ย่อหน้าที่จะถูกนับเป็น "หัวข้อ" ต้องมี**ข้อความชื่อเรื่องต่อท้ายเลขจริงๆ** ไม่ใช่ตัวเลขโดดๆ — กติกานี้ป้องกันไม่ให้ระบบเข้าใจผิดว่าค่าสถิติในตาราง เช่น "67.00" หรือ "40.5" เป็นหัวข้อ (เพราะมันมีรูปแบบเป็นตัวเลขจุดเหมือนหัวข้อ x.x เป๊ะ แต่ไม่มีข้อความต่อท้าย)

### กรณีกำกวม: "เลขเปล่า" (1. 2. 3. ไม่มีจุด)

ปัญหาคือเลขแบบนี้บางเอกสารใช้เป็น**หัวข้อใหญ่จริงๆ** (เหมือน "บทที่") แต่บางเอกสารใช้แค่เป็น**รายการย่อยธรรมดา** (เหมือน bullet list) — หน้าตาเหมือนกันเป๊ะ แยกไม่ออกจากตัวอักษรอย่างเดียว

ระบบแก้ปัญหานี้ด้วยการ**ดูบริบทที่ปรากฏก่อนหน้า**: ถ้ายังไม่เคยเจอหัวข้อแบบมีจุด (เช่น "1.1") มาก่อนในบทนั้นเลย เลขเปล่าตัวแรกที่เจอมักจะเป็นหัวข้อใหญ่จริง แต่ถ้าเจอหัวข้อลึกๆ มาก่อนแล้ว (เช่น "3.3.1") เลขเปล่าที่โผล่มาทีหลังมักจะเป็นแค่รายการย่อย ถ้ายังตัดสินใจไม่ได้ชัดเจน ระบบจะดูเพิ่มว่าระยะเยื้องเดิมของย่อหน้านั้น "ย่อกลับ" มาชิดซ้ายกว่าอันก่อนหน้าอย่างชัดเจนหรือไม่ (สัญญาณของการขึ้นหัวข้อใหม่) — ถ้ายังกำกวมอยู่จริงๆ ระบบจะไม่เดา แต่จะแจ้งเตือนให้ผู้ใช้ตรวจสอบเอง

## ตรรกะการกำหนดระดับ Heading

กติกาพื้นฐาน: นับจำนวนจุดในเลขนำหน้า แล้วบวกเข้ากับ "ค่าเริ่มต้น" เพื่อได้ระดับ Heading เช่น "บทที่" = ระดับ 1, "1.1" (1 จุด) = ระดับ 2 หรือ 3 (แล้วแต่เอกสาร), "1.1.1" (2 จุด) = ระดับถัดไป และไล่ต่อไปเรื่อยๆ

**จุดที่ฉลาดที่สุดของระบบ:** ค่าเริ่มต้นนี้**ไม่ตายตัว** เพราะพบจากการทดสอบจริงว่าแต่ละเอกสาร/แต่ละสถาบันมีธรรมเนียมไม่เหมือนกัน (บางที่ให้ "1.1" เป็น Heading2 บางที่ให้เป็น Heading3) ระบบจึง**สแกนหา Style ที่ผู้เขียนตั้งไว้เองแล้วจริงๆ**ในเอกสารก่อน แล้วเดาค่าที่เหมาะสมที่สุดให้อัตโนมัติ พร้อมอธิบายเหตุผลให้ผู้ใช้เห็น (เช่น "ตรวจพบจาก Style เดิม 9 หัวข้อ") — และผู้ใช้สามารถเปลี่ยนเองได้ทันทีถ้าไม่ตรงกับที่ต้องการ โดยไม่ต้องสแกนไฟล์ใหม่

## ตรรกะการจัดระยะเยื้อง (Staircase Indent)

แนวคิดคือให้แต่ละระดับหัวข้อเยื้องเข้าไปแบบขั้นบันได โดย**หัวข้อลูกจะเริ่มตรงตำแหน่งที่ "ข้อความ" ของหัวข้อแม่เริ่มพิมพ์** (ไม่ใช่ตรงตำแหน่งตัวเลขของหัวข้อแม่) ระบบคำนวณความกว้างจริงของตัวเลขแต่ละหัวข้อด้วยฟอนต์และขนาดจริงของไฟล์นั้น แล้วปัดตำแหน่งให้ตรงกับ "จุดหยุด Tab" ที่ Word ใช้จริง (ไม่ใช่คำนวณแบบชิดท้ายเลขพอดี เพราะ Word ไม่ได้ทำงานแบบนั้น)

ย่อหน้าเนื้อหาที่ไม่มีเลขนำหน้าเลย จะเกาะตำแหน่งเดียวกับหัวข้อที่ใกล้ที่สุดก่อนหน้ามันเสมอ ส่วนบรรทัดที่ 2 เป็นต้นไปของทุกย่อหน้าจะกลับไปชิดซ้ายสุดของหน้าเสมอ

## หลักการที่ยึดถือตลอดการออกแบบ

1. **ไม่แตะเนื้อหา** — ไม่มีการเปลี่ยนคำ ตัวเลข หรือสัญลักษณ์ใดๆ ในเอกสารเลย ปรับแค่ "รูปแบบ" เท่านั้น
2. **ไม่แตะขนาดฟอนต์หรือระยะห่างบรรทัด** — เป็นสิทธิ์ของเจ้าของเอกสาร ระบบไม่เข้าไปยุ่งเกี่ยวเด็ดขาด
3. **ไม่เดาโดยไม่มีหลักฐาน** — ทุกการตัดสินใจของระบบ (ระดับ Heading, ขนาดตัวอักษรที่แสดงให้ดู ฯลฯ) มาจากการอ่านค่าจริงในไฟล์เสมอ ถ้าไม่มีหลักฐานพอ ระบบจะแจ้งเตือนแทนการเดา
4. **โปร่งใสทุกขั้นตอน** — ก่อนแก้ไขจริงทุกครั้ง ผู้ใช้จะเห็นตารางเสนอการเปลี่ยนแปลงและต้องกด "อนุมัติ" เองเท่านั้น ไม่มีการแก้ไขแบบเงียบๆ
5. **ระมัดระวังเป็นพิเศษกับตาราง** — เนื้อหาที่อยู่ในตารางส่วนใหญ่จะไม่ถูกแตะ ยกเว้นกรณีที่ชัดเจนมากว่าเป็นหัวข้อจริง (มีข้อความต่อท้ายเลขชัดเจน) แม้จะอยู่ในตารางที่ไม่มีเส้นขอบ (ใช้เป็นกลไกจัดหน้าเอกสาร) ก็ตาม
